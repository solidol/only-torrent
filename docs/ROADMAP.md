# План Only Torrent

## Збереження та локалізація

З 0.3.1: конфігурація settings.json, окремі JSON задач у Tasks, бінарні покоління fast-resume у Resume, службові torrent за info-hash. INI, SQLite та FireDAC вилучені; міграції попереднього сховища немає. Мовні каталоги залишаються JSON UTF-8. Подробиці й механізм відновлення: [STORAGE.md](STORAGE.md).

## Подальші етапи

1. **Базова мережа та .torrent.** Завершити й перевірити DLL/Delphi integration; локальний seed → download із перевіркою SHA-1; HTTP та UDP tracker; multi-file та Unicode; помилки диска; відновлення списку й fast-resume; завершення без зависання UI. Перевірити Windows 7 SP1 та сучасну Windows x64. До виконання цих перевірок не називати 0.1 готовим клієнтом.
2. **Магнети.** Асинхронне отримання метаданих, скасування, таймаути, DHT і передавання прямих пірів реалізовані та перевірені. Системні асоціації .torrent/magnet і передавання запитів відкритому екземпляру зібрані й перевірені в ізольованому реєстрі та через команду обробника. Фактичний вибір defaults/клік браузера і Windows 7 залишаються для ручної перевірки: [SYSTEM-ASSOCIATIONS.md](SYSTEM-ASSOCIATIONS.md). HTTP/HTTPS і папка автопідхвату також реалізовані: [TORRENT-SOURCES.md](TORRENT-SOURCES.md).
3. **Мови.** Першочергову реалізацію JSON-локалізації перенесено до P0 вище; надалі розширювати переклади й перевіряти повноту ключів.
4. **DHT.** Увімкнення за налаштуванням і пошук magnet реалізовані; залишаються постійне збереження таблиці вузлів і розширені параметри bootstrap.
5. **Проксі.** SOCKS5/HTTP за підтримкою рушія, окремі параметри tracker/peer та перевірка відсутності витоку DNS.
6. **Веб-інтерфейс.** Окремий transport adapter до сервісу керування торрентами. Жодних VCL-посилань у серверному коді; команда/запит/знімок стану; виклики рушія серіалізовані. У першій версії жодного HTTP-listener.

## Ручне оновлення — реалізовано й перевірено на синтетичних пакетах

Додано окремий `otupdater.exe`: перевірка GitHub, завантаження ZIP/SHA-256,
валідація пакета та ручне встановлення з резервними копіями. Жодних автоматичних
перевірок при запуску чи за розкладом. Апдейтер включено до сценарію пакування,
збирання, встановлення та відкат перевірені в ізольованих папках; деталі й
обмеження: [UPDATER.md](UPDATER.md).

## Продуктивність та розмір — подальші роботи

Мережеві/дискові потоки належать libtorrent. VCL не хешує й не качає дані. Поточний C ABI викликається лише UI-потоком. Перед веб-етапом додати чергу команд у сервісному шарі.
Не робити висновків про швидкодію без вимірювань: заміряти idle CPU/RAM, 1/10/100 активних торрентів, hash throughput, disk throughput та час завершення.
Початковий список — native TListView. При тисячах записів перейти на OwnerData зі знімками, уникати повного оновлення незмінених рядків.
Release: оптимізація, без debug symbols, map та BPL; статичне компонування потрібних VCL units, без зайвих бібліотек. Не застосовувати UPX як заміну аналізу розміру. Вимірювати суму EXE + DLL, а не лише EXE.

## Відокремлення libtorrent — виконано

Оригінальна `torrent-rasterbar.dll` і окремий `ltbridge.dll`; обчислення — в Delphi-модулях `src/core`. Пакет рушія збирається незалежно від EXE. Під час відокремлення перевірено незмінність EXE після перезбирання моста, усіх DFM та контрольного зображення прогресу. Згодом для P0 у налаштуваннях додано мову й папку торрентів. Деталі й межі сумісності: [ENGINE-ARCHITECTURE.md](ENGINE-ARCHITECTURE.md).

## Межі ABI v2

cdecl; Win64; UTF-8 вхід/вихід; snapshot = 1064 байти з вирівнюванням 8. Пам’ять ніколи не звільняється іншим runtime. Винятки C++ не перетинають ABI. Ідентифікатори стабільні протягом сесії; remove зберігає файли. lt_error повертає thread-local текст до наступної помилки на тому ж потоці.
