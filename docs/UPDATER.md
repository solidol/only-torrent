# Ручне оновлення

`otupdater.exe` — окремий Delphi/VCL застосунок Windows x64. Йому не потрібні
libtorrent, ltbridge чи SQLite. Форму збережено в `Ot.UpdaterForm.dfm`.

1. Only Torrent → Налаштування → Перевірити оновлення.
2. Апдейтер перевіряє останню стабільну версію при відкритті вікна.
   Єдина кнопка «Оновити» активується лише за наявності новішої версії.
3. Закрити Only Torrent повністю й натиснути «Оновити». Завантаження,
   перевірка SHA-256 ZIP, переліку файлів, хешів і версій обох EXE та
   встановлення виконуються послідовно, без додаткових кнопок і підтверджень.
4. Запустити Only Torrent вручну. Якщо встановлення не вдалося через відкритий
   клієнт, закрити його й повторно натиснути «Оновити»; перевірений пакет зберігається.

Немає таймерів перевірки оновлень у головному застосунку, запуску разом із Windows,
служб, планувальника задач або автоматичного встановлення/перезапуску.
Таймер форми апдейтера лише відображає результат явно запущеного worker-потоку.
Закриття вікна скасовує перевірку або завантаження; мовчазний сервер може затримати скасування до мережевого
таймауту. Під час заміни файлів закриття вікна тимчасово заблоковане.

## Джерело та перевірка

Офіційне джерело — `solidol/only-torrent`, GitHub Releases API `/releases/latest`.
Приймаються лише опубліковані стабільні релізи, тег `vMajor.Minor.Release.Build`,
ZIP `Only-Torrent-<version>-Win64.zip` і відповідний `.zip.sha256`.
Порівняння всіх чотирьох чисел, без зниження або повторного встановлення версії.
URL вкладень мають відповідати цьому репозиторію, тегу й імені пакета.
Мережа — HTTPS через системний WinHTTP, штатна перевірка сертифікатів, до 5
перенаправлень. Для Windows 7 потрібні системні оновлення TLS/кореневих сертифікатів;
сумісність з GitHub на цій ОС ще потребує перевірки. Ланцюжок
перенаправлень забороняє перехід на HTTP. Токен GitHub не потрібний;
обмеження публічного API або помилки сервера показуються користувачу.

ZIP обмежений 128 MiB, розпакований вміст — 512 MiB, до 128 записів. Кожен файл
не більше 128 MiB; розпакування потоком також обмежує фактичний розмір.
Заборонені довільні шляхи, дублікати імен, traversal, ADS, junction/symlink у
шляхах призначення. Дозволено лише відомі файли програми, дві мови й ліцензії.

`release.json.packageFiles` містить SHA-256 кожного файла пакета, крім самого
release.json; цілісність цього manifest забезпечує хеш ZIP. Старі пакети без
packageFiles та апдейтера встановлювати через цей інструмент не можна.
HTTPS і checksum захищають передавання та виявляють пошкодження; це не окремий
криптографічний підпис видавця. Authenticode/підписаний update manifest не реалізовані.

## Встановлення й резервні копії

Меню запускає тимчасову копію EXE; прямий запуск `otupdater.exe` без аргументів
так само відкриває тимчасову копію. Це дозволяє замінювати встановлений апдейтер.
Мова береться з головного застосунку, при прямому запуску — українська.

Потрібні права запису в папку програми. Підвищення прав та примусового завершення
процесів немає. Заблоковані файли спричиняють помилку перед встановленням.
Оновлення не торкається профілю, tasks.db, settings.ini або даних торрентів.
Файли, яких немає в новому пакеті, автоматично не видаляються.

Перед зміною створюється `.ot-update-backup-{GUID}` у папці програми: копії старих
файлів та `update-files.txt`. Нові файли копіюються у тимчасові сусідні файли,
потім замінюються через MoveFileEx з WRITE_THROUGH. При помилці виконується
зворотне відновлення вже замінених файлів. Резервні копії залишаються й після
успіху. Автоматичне відновлення після вимкнення живлення не реалізоване: за потреби
повернути файли з резервної папки вручну, не запускаючи частково оновлений клієнт.
Перед заміною записується `.ot-update.pending` з версією і шляхом резервної папки.
При успіху або успішному відкаті маркер видаляється; при перериванні чи невдалому
відкаті лишається. Новий клієнт блокує запуск за наявності маркера або активного
install-lock. Після ручного відновлення прибрати `.ot-update.pending`.

ZIP, checksum і stage зберігаються в `%TEMP%\OnlyTorrent-Update-{GUID}`. Тимчасові копії апдейтера
та резервні папки не видаляються автоматично; їх можна прибрати після перевірки
оновленої програми. Профіль користувача для кешу не використовується.

## Збирання та стан

Відкрити `otupdater.dproj` у RAD Studio або за явною вимогою виконати:

```powershell
powershell -ExecutionPolicy Bypass -File tools/build-ide.ps1 -Updater
```

Ресурс версії апдейтера генерується з поточної version.json без окремого інкременту:
релізний комплект має одну версію. `build-release.ps1` послідовно збирає клієнт,
апдейтер, перевіряє збіг версій та додає обидва EXE до ZIP разом з packageFiles.

Реалізацію зібрано й перевірено 14.11.2026: `tests/release_integration.py`,
тести ядра та DFM. Інсталяція/відкат перевірені лише на синтетичних копіях у build;
поточний застосунок не замінювався. Ручний GitHub API check пройшов.
Також пройшло справжнє HTTPS/CDN-завантаження попереднього релізу, перевірка
checksum та розпакування; старий формат відхилено до встановлення.
Докладний обсяг: [VALIDATION.md](VALIDATION.md). Залишаються розширені сценарії:
відсутність мережі до натискання кнопки; новішу/однакову/старішу версію;
404/403/rate limit/обрив/TLS/cancel; пошкоджений SHA й файли; ZIP traversal,
дублі й ліміти; відкритий клієнт, брак прав і місця; успіх і відкат; оновлення
самого апдейтера; збереження профілю; Windows 7 SP1 та Windows 10/11.

API: [GitHub Releases](https://docs.github.com/en/rest/releases/releases).
