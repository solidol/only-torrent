# Збереження завдань і локалізація

Типовий профіль: `%APPDATA%\Only Torrent`. Завантажувані користувацькі дані залишаються у вибраних для завдань папках.

| Розташування | Призначення |
|---|---|
| `settings.ini` | Основна конфігурація, мова, оформлення, мережеві ліміти й типові папки |
| `tasks.db` | SQLite: постійний ID, info-hash, назва, папка даних, службовий torrent, бажаний стан, порядок, дати, параметри файлів і fast-resume BLOB |
| `Torrents\<infohash>.torrent` | Оригінальні метадані завдань у списку, включно із завершеними та призупиненими |
| `Languages\uk-UA.json`, `Languages\en-US.json` поруч з EXE | Каталоги інтерфейсу UTF-8 |

Папка `Torrents` налаштовується через «Налаштування → Папки» або `[Storage] TorrentFolder` в INI. Зміна стосується нових завдань: для наявних БД пам’ятає абсолютні шляхи до їхніх копій. Початковий файл із Downloads після успішного додавання не потрібний.

## INI

Наявний формат продовжує працювати. Додано:

```ini
[Interface]
Language=uk-UA

[Storage]
TorrentFolder=C:\Users\User\AppData\Roaming\Only Torrent\Torrents
```

Мова вибирається в розділі «Інтерфейс» і застосовується без перезапуску. INI не містить списку завдань або resume-даних. Запис INI виконується через тимчасовий файл із подальшою атомарною заміною.

## SQLite та відновлення

`Ot.TaskStore` володіє окремим потоком і з’єднанням SQLite. У поточному коді доступ переведено на FireDAC (`TFDConnection` / `TFDQuery`) через `Ot.Sqlite`; попередній ручний C API видалено. Після переходу збирання й тести ще не виконувалися; аналіз і статус: [FIREDAC-ANALYSIS.md](FIREDAC-ANALYSIS.md). Команди виконуються послідовно. Додавання, зміна бажаного стану та видалення очікують підтвердження запису; періодичні resume-знімки записуються у фоні. Використовуються WAL, `synchronous=FULL`, підготовлені SQL-запити й транзакції. `PRAGMA user_version=1` позначає схему; перше відкриття створює її в транзакції, новіша невідома версія відхиляється без видалення даних. Профіль має файлове блокування одного екземпляра застосунку.

Масиви шляхів, розмірів, пріоритетів, трекерів і параметри завдання зберігаються як версійований JSON у колонці `details` **всередині SQLite**. Окремими JSON-файлами є лише мовні каталоги. Сам `.torrent` у БД не дублюється; fast-resume — двійковий BLOB у колонці `resume`.

Службова копія торрента спочатку повністю записується й атомарно перейменовується, потім підтверджується запис завдання. Після перерваного додавання може залишитися зайва ціла копія, але БД не посилається на напівзаписаний файл. Під час видалення завдання прибирається запис БД; користувацькі файли й службова копія залишаються. Пізня resume-відповідь не може відтворити видалений запис.

Під час запуску відновлюються порядок списку, назви, папки, вибрані файли, їхні ефективні шляхи, трекери, ліміти, послідовне завантаження та бажаний стан «працює / пауза». Статус «роздача» визначає libtorrent за даними. Недоступна папка чи відсутній службовий torrent залишають завдання у списку з помилкою. Інша папка автоматично не підставляється; після відновлення доступу можна натиснути «Пуск».

## Fast-resume

Міст лише адаптує штатні API libtorrent: `save_resume_data`, resume-alerts, `write_resume_data_buf` та `read_resume_data`. Вихідні коди libtorrent незмінні. Усі споживачі alerts використовують один диспетчер, тому звичайне оновлення статусу не відкидає resume-відповіді.

Знімки запитуються раз на 60 секунд із flush дискового кешу. Закриття спершу завершує попередні запити, призупиняє рушій без зміни збереженого бажаного стану, отримує фінальні знімки та завершує чергу SQLite. Інтерфейс продовжує обробляти повідомлення під час очікування. Для кожної фази є тайм-аут 15 секунд; для незавершених фінальних запитів старий resume очищається, щоб наступний запуск виконав перевірку файлів.

Пошкоджений bencode або невідповідний info-hash resume відкидається з переходом до штатної перевірки файлів. Збережені в БД папка, шляхи, пріоритети, трекери, ліміти та бажана пауза мають пріоритет над відповідними полями resume.

## Мовні файли

Обидва каталоги — плоскі об’єкти JSON зі строковими значеннями. Ключі компонентів мають вигляд `FormPreferences.ButtonApply.Caption`; динамічні повідомлення використовують сталі ключі `text.*`, `message.*` і `category.*`. Зміна перекладу не потребує зміни ключа чи перезбирання програми. Форматні параметри `%d`, `%s` тощо потрібно зберігати.

Спочатку читається український каталог, поверх нього — вибраний англійський. Відсутній переклад використовує український. Невалідний каталог не застосовується частково; якщо немає й українського файлу, у коді та DFM залишаються резервні рядки. Технічні повідомлення сторонніх бібліотек можуть надходити англійською.

## Збирання й перевірки

Окрім двох DLL рушія потрібна оригінальна `sqlite3.dll` x64. Усі три готові DLL включено в `third_party/bin/Win64`. Звичайне збирання та `stage-client.ps1` копіюють їх звідти без `deps`, джерел, SDK або мережі. Новий код використовує FireDAC зі встановленої Delphi, динамічний SQLite і вимкнені runtime packages; додаткові BPL та статична копія SQLite не включаються.

```powershell
powershell -ExecutionPolicy Bypass -File tools/build-ide.ps1 -OutputDirectory build/persistence-candidate
powershell -ExecutionPolicy Bypass -File tools/stage-client.ps1
```

Перед останньою командою слід закрити клієнт у папці призначення. Вона складає готовий комплект у `bin/Win64`, включно з мовами, ліцензіями та `client-build.json` із SHA-256. Сценарії IDE використовують спільний mutex і не запускають свої збірки одночасно.

Для необов’язкового оновлення SQLite `tools/fetch-sqlite.py` завантажує офіційну DLL і перевіряє SHA3-256 видавця; результат залишається лише в кеші. Порядок публікації перевірених залежностей: [third_party/README.md](../third_party/README.md).

`OtCoreTests` перевіряє INI, потік SQLite, постійні ID, блокування профілю, JSON/fallback, службову копію після видалення оригіналу, справжні resume-дані та пошкоджений resume. `OtUiSmoke --restore-test` перевіряє відновлення головної форми та коректне закриття. `tests/persistence_restart.py` перевіряє повторні запуски, недоступний диск, відсутній torrent і перервану SQLite-транзакцію. Тести використовують окремі профілі в `build`; `OT_PROFILE_DIR` дозволяє явно вибрати ізольований профіль.

Джерела: [SQLite downloads і контрольні суми](https://www.sqlite.org/download.html), [WAL](https://www.sqlite.org/wal.html), [fast-resume libtorrent](https://libtorrent.org/manual-ref.html#fast-resume).
