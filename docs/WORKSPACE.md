# Робочі файли

Основний застосунок — Delphi 13 CE / VCL, Windows x64. Код тонкого C ABI моста
до libtorrent зберігається в `native`; готовий runtime — у `third_party/bin/Win64`.

## Постійні файли

У Git зберігаються код, DFM, мовні каталоги, ресурси, тести, документація,
сценарії збирання та зафіксований комплект DLL із ліцензіями й SHA-256.
Історичні зразки логотипа в `resources` залишаються частиною дизайну.

`bin/Win64` містить поточні EXE, runtime і зібрані тести. Це ігнорований
результат збирання, а не джерело DLL для релізного пакування.

## Вміст build

Під час очищення залишати:

- Останній релізний пакет та його підготовлену папку, ZIP, MSI і SHA-256.
- Інструменти `wix314`, `gh-cli`, `icon-tools`, потрібні сценаріям із `tools`.
- `update-old-fixture` — попередній EXE для перевірок оновлення й відкату;
  це потрібні тестові дані, а не невикористаний реліз.
- `update-client-fixture` — безпечний тестовий клієнт для сценарію перезапуску.
- Поточний `core-fixture`, профіль із `persistence-profile.path` та ресурси версії,
  які потрібні окремому збиранню й запуску тестових проєктів.
- Останні журнали, знімки та зведення перевірок, включно з каталогом журналів,
  на який посилається `full-validation-summary.json`.

Старі релізні пакети, проміжні DCU/CMake/MSI каталоги, одноразові сценарії
редагування й пакування та завершені тестові каталоги можна видаляти.
Видалення з локальної робочої папки не видаляє опубліковані релізи GitHub.

`deps` — необов'язковий кеш вихідних залежностей і SDK для явного перезбирання
рушія. Звичайне Delphi-збирання їх не використовує. Не видаляти його під час
роботи сценарію оновлення рушія або перевірки upstream integrity.

Перед рекурсивним видаленням перевіряти абсолютні шляхи, активні процеси й
відсутність junction/symlink, які можуть вести за межі робочої папки.
Профіль `%APPDATA%\Only Torrent` і користувацькі завантаження не є кешем збирання.
Очищення не запускає збирання, тести, застосунок або публікацію.
