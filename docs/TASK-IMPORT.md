# Імпорт задач

Команда **Файл → Імпорт задач з BitComet / µTorrent…** відкриває окрему DFM-форму.
Виберіть клієнт, файл профілю, натисніть «Прочитати список», позначте потрібні
задачі й натисніть «Імпортувати вибрані». Діалог показує прогрес і результат кожної
задачі; зупинення залишає вже додані задачі.

Профіль джерела читається в окремому потоці. За замовчуванням пропонується
`%APPDATA%\BitComet\Downloads.xml` або `%APPDATA%\uTorrent\resume.dat`;
можна вибрати профіль портативної версії вручну. Автоматичного імпорту немає.
Вихідний клієнт треба закрити, щоб отримати узгоджений знімок стану.

Підтримувані дані:

- BitComet: `BitComet/Torrents/Torrent` у Downloads.xml, кеш `.torrent` і
  однойменний XML у Torrents; SaveLocation / SaveDirectory + SaveName,
  FileList з відносними шляхами, розмірами, StartAt і Priority (-1 — пропуск).
  Формат звірено читанням локального профілю BitComet 2.23.
- µTorrent: bencode resume.dat; ключі `.torrent`, path, info, caption, prio,
  trackers. Для багатофайлової задачі path є коренем вмісту, для однофайлової —
  повним іменем файла. Нестандартні targets / mapped_files не імпортуються.
- Вибір файлів зберігається; вибрані файли отримують звичайний пріоритет Only
  Torrent. Індивідуальні ліміти, статистика, черга і службові fast-resume інших
  клієнтів не переносяться. HTTP/FTP-задачі та магнети без `.torrent` не підтримуються.

За замовчуванням задачі додаються **призупиненими**, без мережевої сесії й без читання даних
завантаження. Копіюється лише `.torrent` у керований кеш; запис задачі потрапляє
в SQLite. Повторний info-hash пропускається. Відсутні каталоги не створюються
і не підміняються каталогом завантажень за замовчуванням. Відсутні або
неоднозначні карти файлів, тимчасові розширення `.bc!` / `.!ut` повідомляються
як помилки, а не вгадуються. Дані джерела не перейменовуються і не видаляються.

Для призупиненої задачі доступна команда **Примусово перевірити дані**.
Міст `ltbridge.dll` викликає штатні force_recheck / stop_when_ready libtorrent:
перевірка виконується асинхронно, прогрес і карта блоків оновлюються звичайним
опитуванням. Після ручної перевірки задача залишається призупиненою. Під час
перевірки запуск заблокований, пауза дозволяє зупинити перевірку. Старий
fast-resume скидається перед перевіркою; після її завершення запитується новий.

У діалозі імпорту є два незалежні чекбокси, вимкнені за замовчуванням:

- **Перевірити файли одразу** — поставити нові задачі на перевірку після додавання;
  без автозапуску вони залишаться призупиненими після перевірки.
- **Автоматичний запуск задачі** — перевірити файли й продовжити завантаження або
  роздачу після завершення перевірки. Для непідтверджених задач перевірка обов’язкова,
  навіть якщо перший чекбокс вимкнено.

`needsVerification` зберігається в JSON `details` запису SQLite без зміни схеми БД.
Імпортовані задачі та старі записи без цього поля вважаються непідтвердженими.
Під час їхнього запуску старий fast-resume не використовується: спочатку виконується
повне перерахування хешів. Ознака скидається після успішного завершення перевірки;
пауза або помилка залишають її встановленою. Намір автозапуску зберігається в
`running`; після перезапуску незавершена перевірка має виконатися повторно.

У головному списку доступне множинне виділення через Ctrl і Shift. Команди
видалення, запуску та паузи застосовуються до виділення. Перевірка хешів — до
виділених призупинених задач, які ще не перевіряються й не видаляються.
Перед пакетним видаленням показується одне підтвердження з кількістю задач,
типовий вибір — «Ні». Помилка окремої задачі не зупиняє решту; подробиці
записуються в журнал, після операції показується кількість помилок.

Парсер bencode обмежує розмір файла (64 MiB), вкладеність (64) і кількість
вузлів (250000). XML також обмежено 64 MiB; DTD та ENTITY заборонено.
Відносні шляхи проходять ту саму перевірку, що й збережені задачі.

Контекстне меню й панель інструментів мають окремі команди видалення задачі
зі збереженням даних і видалення задачі разом з даними. Обидві вимагають
підтвердження, типовий вибір — «Ні». Видалення даних виконує libtorrent
лише для файлів цієї задачі, без Кошика. Запис SQLite залишається призупиненим
до отримання torrent_deleted_alert; у разі torrent_delete_failed_alert запис
зберігається, задача позначається помилкою, причина записується в журнал.

Джерела опису форматів і поведінки:

- [Файли профілю BitComet](https://wiki.bitcomet.com/files-used-by-bitcomet/).
- [Авторський конвертер resume.dat з µTorrent](https://gist.github.com/helix84/56710049d76ade7bce6aa59bbfbccf74)
  (аналіз ключів, без включення його коду в проєкт).
- [Перевірка без початку завантаження у libtorrent](https://www.libtorrent.org/manual-ref.html).

Збирання та тести виконуються лише за окремою вимогою. Імпорт на реальному
профілі користувача не запускати як автоматичний тест.

14.11.2026 за явною вимогою виконано тест `tests/bitcomet_import.py` через
справжній діалог: 27 задач прочитано, 25 додано призупиненими в ізольований
профіль; 2 відхилено через `.bc!`. Повторний імпорт пропустив усі 25 дублікатів.
Перевірено SQLite quick_check, збережені шляхи, розміри та вибір файлів,
керовані копії torrent, відсутність resume і завершення прогресбару.
SHA-256 файлів вихідного профілю до й після тесту збігаються.
Основний EXE і UI-тест зібрано Release / Win64. Виявлену під час тесту
помилку фабрики FireDAC усунуто явним підключенням модулів реєстрації.
