# Джерела torrent-файлів

## HTTP/HTTPS і magnet

**Файл → Додати HTTP / magnet-посилання…**, Ctrl+U, відкриває DFM-форму
`FormAddLink`. Кнопка «Отримати торрент» запускає фоновий `TOtTorrentSource`.
UI залишається доступним для скасування, поточні задачі продовжують працювати.
Після отримання метаданих відкривається звичайний діалог папки й вибору файлів:
можна завантажити зараз, додати призупиненим або скасувати додавання.
Усі нові задачі спочатку мають непідтверджений стан файлів. При виборі запуску
виконується хешування й лише потім починається завантаження; при додаванні на
паузі ця ознака зберігається до наступного запуску задачі.

HTTP використовує `System.Net.HttpClient.THTTPClient`, системний WinHTTP/TLS,
без додаткової SSL DLL. Дозволені лише HTTP/HTTPS, без вбудованих логіна й
пароля. Сертифікати перевіряються системою; обхід перевірки не застосовується.
Дозволено до 5 перенаправлень. Розмір відповіді обмежено 64 MiB також на рівні
потоку запису; відповідь має статус 200 і синтаксично коректний bencode з info.
Повну перевірку метаданих виконує libtorrent перед додаванням задачі.
Обмеження з’єднання/відправлення — 10 с, очікування відповіді — 15 с,
загальне очікування — 120 с. Скасування перевіряється під час приймання даних;
якщо сервер мовчить, діалог чекає завершення поточного мережевого таймауту.

Magnet отримує метадані через штатний `ut_metadata` libtorrent. Окрема
тимчасова сесія використовує `upload_mode` й `disabled_storage_constructor`:
файли роздачі не завантажуються й не створюються. Коли метадані готові,
`create_torrent(torrent_info)` зберігає оригінальний info-словник та info-hash.
Потрібен SHA-1 magnet (`urn:btih`); v2-only магнети поточним libtorrent 1.2
не підтримуються. Отримання залежить від доступності пірів з метаданими;
сама назва dn не містить списку файлів чи хешів частин. Приватний пір може
не надавати метадані через цю розширену функцію протоколу.

Початковий magnet зберігається в JSON `details.magnet` запису SQLite.
Трекери та прямі піри `x.pe` передаються звичайній сесії, також під час
відновлення задачі після перезапуску. Успішне додавання magnet вмикає DHT
у загальних налаштуваннях і поточній сесії, щоб працювали посилання без
трекерів. Перемикач доступний у **Налаштування → З’єднання**; private torrents
обробляються за правилами libtorrent. Для отримання самих метаданих
тимчасова сесія використовує DHT незалежно від загального перемикача.
Постійне збереження таблиці DHT-вузлів поки не реалізовано.

Відповідь тимчасово записується в профіль/Incoming, перевіряється й копіюється
в керовану папку Torrents. Тимчасовий файл прибирається також після скасування
звичайного діалогу. Повторний info-hash не створює нової задачі.

## Папка автопідхвату

**Налаштування → Автопідхват**: увімкніть обробку та виберіть наявну папку.
За замовчуванням функція вимкнена. INI: `[Watch] Enabled` та `Folder`.
Автопідхват не створює відсутній каталог і не дозволяє вибрати папку
керованого кешу Torrents як джерело.

`TimerWatch` раз на секунду перевіряє лише `.torrent` без рекурсії. Стабільними
вважаються файли, чий розмір і час модифікації не змінювались щонайменше
1,5 секунди; відкриті на запис файли пропускаються до звільнення. Файли
обробляються невеликими порціями, без діалогу додавання, з поточними
налаштуваннями папки та автоматичного запуску. Під час інших діалогів додавання
автопідхват призупиняється, щоб не відкривати накладених вікон.

Оригінали не видаляються й не переміщуються, дублікати пропускаються за
info-hash. Помилка окремого файла потрапляє в журнал, без спливаючого вікна;
змінений файл буде розглянуто повторно. Після перезапуску незмінні джерела
переглядаються ще раз, але наявні задачі не створюються повторно.
Щоб явно видалена задача не додавалася після наступного запуску, приберіть
відповідний вихідний .torrent із папки автопідхвату або вимкніть її обробку.

## Перевірки

`tests/torrent_sources.py` запускає справжні VCL-діалоги в окремих профілях
і локальний HTTP/HTTPS-сервер. Перевіряються отримання, перенаправлення,
404, HTML, надмірний Content-Length, цикл перенаправлень, скасування,
заборонена схема та недовірений TLS-сертифікат. Локальний пір перевіряє
отримання magnet-метаданих без payload, а потім — фактичне завантаження
синтетичних даних через звичайну задачу. Автопідхват перевіряється також
після перезапуску, з дублікатами, помилковими й незавершеними файлами.

`tests/magnet_metadata.py "magnet:?..."` — лише явна ручна перевірка
наданого посилання: зберігає .torrent в build/magnet-metadata, перевіряє
info-hash, не завантажує файли роздачі. Публічні посилання не включаються
в автоматичний локальний набір тестів.

Нові C ABI 2 експорти моста: `lt_magnet_open/poll/close`, `lt_apply_magnet`,
`lt_discovery`. Структури попереднього ABI не змінені. Оригінальний
`torrent-rasterbar.dll` у комплекті залишився побітово незмінним.
